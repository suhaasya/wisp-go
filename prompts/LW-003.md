## Goal
Serve the app only to the person who launched it: loopback-only listener, per-launch token exchanged for cookies, CSRF header, Origin and Host checks, strict CSP.

## Why this matters
A local web server can be reached by other local programs and by any website open in the same browser. This middleware is what makes a web UI acceptable for a tool that holds production database passwords.

## What to build (do these steps in order)
1. Listen with net.Listen("tcp", "127.0.0.1:<port>"); refuse any non-loopback address even if passed by flag. Set ReadHeaderTimeout 5 s, IdleTimeout 120 s, MaxHeaderBytes 64 KB.
2. At launch create launchToken (32 random bytes, base64url). The launcher opens /auth/exchange?t=<launchToken>. The handler validates in constant time, sets cookie wisp_sid (random session id, HttpOnly, SameSite=Strict, Path=/, no Expires) and redirects to / with 303 so the token leaves the address bar. Launch tokens are single-use and expire after 60 s; handoff (LW-002) mints new ones.
3. Session store: map of sid → {csrfToken, created}; GET /api/v1/hello returns the CSRF token to the page.
4. Middleware order: Host check (exactly 127.0.0.1:<port> or localhost:<port>, else 421) → auth (all paths except /auth/exchange and static assets need a valid cookie, else 401) → for non-GET/HEAD: Origin must equal http://127.0.0.1:<port> or http://localhost:<port> and header X-Wisp-CSRF must match (else 403).
5. Headers on every response: Content-Security-Policy "default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'", X-Content-Type-Options nosniff, Referrer-Policy no-referrer, Cache-Control no-store for /api/*. Never send Access-Control-* headers.
6. Static assets: hashed files under /assets/ get Cache-Control immutable; index.html no-store. index.html is rendered per request with a fresh random style nonce placed in <meta name="csp-nonce"> and in the CSP as style-src 'self' 'nonce-<n>' (CodeMirror injects styles and needs it, see LW-031).
7. Security tests: wrong Host, missing cookie, wrong Origin, missing CSRF header, reused launch token, expired launch token, and a cross-origin fetch simulation all rejected.

## Acceptance criteria (every one must pass)
- Every rejection case in the steps returns the specified status (tested).
- A page served from another origin cannot read or modify data through the API (tested with httptest and forged headers).
- No response contains Access-Control-Allow-Origin.
