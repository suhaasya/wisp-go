## Goal
Define, persist and serve connection profiles (without secrets) through the API.

## Why this matters
The connections screen, the form, sessions and the title bar all read profiles. One model and API keeps them consistent.

## What to build (do these steps in order)
1. Profile struct (see interface); stored in config/connections.json {version, folders[], connections[]}; ids are UUIDv7 strings (github.com/google/uuid allowed? prefer a 20-line local v7 generator to avoid a dependency).
2. API: GET /connections (list with folders), POST (create; body may include password which goes to Secrets and is never stored in JSON), PUT /{id} (password field optional: absent = unchanged, empty string = delete), DELETE /{id} (also deletes secrets), POST /{id}/duplicate (copies secrets).
3. Responses carry hasPassword: true/false, never the password.
4. Corrupt file: rename to .bak-<timestamp>, start empty, return a warning flag the page can show.

## Files to create or change
- internal/store/profiles.go (+ test)
- internal/api/connections.go

## Interface to implement (adapt names if needed; keep the shape)
```go
type Profile struct {
  ID, Name, Folder string; Engine string /* postgres|mysql|mariadb */
  Transport Transport /* {Kind: tcp|socket|pipe, Host, Port, Path} */
  User, Database string; PasswordMode string /* keychain|ask|none */
  SSL SSLConfig; SSH *SSHConfig; Env string /* local|development|staging|production */
  ReadOnly, SafeMode bool; Options ConnOptions; LastUsed *time.Time }
```

## Acceptance criteria (every one must pass)
- Profiles round-trip unchanged.
- No API response contains a stored password.
- Delete removes the profile's secrets.
