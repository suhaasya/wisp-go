## Goal
Every colour, font size, radius and spacing value from the mockup becomes a Tailwind v4 theme token, with light and dark themes and a system default.

## Why this matters
After this ticket, agents style with token utilities (bg-panel, text-ink-2) instead of reading CSS from the mockup. It is the single source of visual truth.

## What to build (do these steps in order)
1. In app.css add `@theme { --color-canvas: #E9ECF1; --color-window: #FBFCFD; ... }` for every token in the pack's Design tokens page (canvas, window, sidebar, panel, raise, ink, ink-2, ink-3, line, line-2, accent, accent-soft, env-local, env-dev, env-staging, env-prod, modified, modified-line, inserted, deleted, syn-*, null-text).
2. Add font tokens: --font-sans (system stack: -apple-system, 'Segoe UI', Roboto, Ubuntu, sans-serif), --font-mono (ui-monospace, 'SF Mono', Menlo, Consolas, 'DejaVu Sans Mono', monospace); text sizes 11.5px, 12.5px, 13px, 15px; radii --radius-control 7px, --radius-card 10px, --radius-dialog 12px.
3. Dark theme: `[data-theme=dark] { --color-canvas: #0F1216; ... }` overriding the same variables; `@custom-variant dark (&:where([data-theme=dark], [data-theme=dark] *));`.
4. Base layer: body uses bg-canvas text-ink font-sans text-[13px]; focus-visible ring 2px accent offset 1px; scrollbar styling subtle.
5. theme.ts: setting light|dark|system; system follows matchMedia('(prefers-color-scheme: dark)') changes; sets data-theme on <html>.
6. tools/check-classes.ts scans web/src for class strings containing arbitrary colour values like bg-[#...] or text-[rgb(...)] and fails; wire into `npm run check`.

## UI specification
- Token names map 1:1 to the mockup CSS variables (--ink2 → --color-ink-2).
- No bundled fonts: system font stacks only.
- Use only Tailwind theme-token utilities (LW-007) and the Preact components in web/src/ui/ (LW-008); no arbitrary colour values, no new UI libraries.
- Check both light and dark themes against the screenshots.

## Acceptance criteria (every one must pass)
- Switching theme updates the whole page instantly without reload.
- CSS gzip size stays ≤ 15 KB with the base layer.
- check-classes fails on an arbitrary hex colour class.

## How to work
Follow the TDD skill (.claude/skills/tdd/SKILL.md) and AGENTS.md section 6.
1. First reply with a plan: files you will touch, approach per step, and how each acceptance criterion will be proven.
2. In the same reply, list the seams you propose to test (start from the section above). For each: the public interface, one line on what it catches, one line on what it misses. Then STOP and wait for me to confirm the seams. Do not write any test or code before that. (If this ticket has no code under test, say so and continue.)
3. After confirmation, work in vertical slices: one seam, one failing test (red), the minimal code to pass it (green), run the tests, commit. Repeat. Never write all tests first.
4. Test only through public interfaces; fake only system boundaries (database, network, clock, filesystem). Expected values come from the spec or literals, never recomputed like the code does.
5. Do not refactor inside the loop; collect refactor ideas for the report.
6. Commit messages start with the task id (e.g. "LW-007: add ..."). If the task conflicts with AGENTS.md, docs/PRD.md or existing code, stop and explain instead of guessing. Do not start the next ticket.
