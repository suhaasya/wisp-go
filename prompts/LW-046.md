## How to work
Follow the TDD skill (.claude/skills/tdd/SKILL.md) and AGENTS.md section 6.
1. First reply with a plan: files you will touch, approach per step, and how each acceptance criterion will be proven.
2. In the same reply, list the seams you propose to test (start from the section above). For each: the public interface, one line on what it catches, one line on what it misses. Then STOP and wait for me to confirm the seams. Do not write any test or code before that. (If this ticket has no code under test, say so and continue.)
3. After confirmation, work in vertical slices: one seam, one failing test (red), the minimal code to pass it (green), run the tests, commit. Repeat. Never write all tests first.
4. Test only through public interfaces; fake only system boundaries (database, network, clock, filesystem). Expected values come from the spec or literals, never recomputed like the code does.
5. Do not refactor inside the loop; collect refactor ideas for the report.
6. Commit messages start with the task id (e.g. "LW-046: add ..."). If the task conflicts with AGENTS.md, docs/PRD.md or existing code, stop and explain instead of guessing. Do not start the next ticket.

## Final report
End with the report format from AGENTS.md section 8: summary, files changed, confirmed seams and the tests written for each, each acceptance criterion with PASS/FAIL and evidence, measurements, dependencies added, refactor ideas, open questions.
