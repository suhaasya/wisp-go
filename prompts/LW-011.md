# Task LW-011: Secret storage: OS keychain and encrypted fallback
Milestone M0 (Foundations) · Priority P0 · Estimate 2 d · Step 11 of 48

## Goal
Passwords, SSH passphrases and tokens are stored only in the OS keychain (or an encrypted file when none exists) and are never sent back to the page.

## Why this matters
The server holds the most sensitive data in the product. Pure-Go keychain access keeps CGO off.

## What to build (do these steps in order)
1. Interface Get/Set/DeleteAll keyed by profile id and kind; service name 'dev.wisp'.
2. Keyring backend via github.com/zalando/go-keyring (macOS security CLI, Windows Credential Manager, Linux Secret Service over D-Bus).
3. Probe availability at startup; if unavailable, use the file backend: secrets.bin in data dir, key from a master password via argon2.IDKey(t=3, m=64 MiB, p=1), XChaCha20-Poly1305 per record, random nonce. The page prompts for the master password through an API when needed (POST /api/v1/secrets/unlock).
4. Zero byte slices after use where possible; never log values; String() methods redact.

## Interface to implement (adapt names if needed; keep the shape)
```go
type SecretKind string // "db_password" | "ssh_password" | "ssh_passphrase"
type Secrets interface {
  Get(profileID string, kind SecretKind) ([]byte, bool, error)
  Set(profileID string, kind SecretKind, value []byte) error
  DeleteAll(profileID string) error }
```

## Acceptance criteria (every one must pass)
- No password appears in any file in config or data dirs after saving one (grep test).
- API responses never contain stored secrets.
- File backend round-trip works and wrong master password fails cleanly.

## Proposed seams and tests (starting point: confirm the seams with me before writing any test)
- Backend tests with the keyring mock (keyring.MockInit()) and the file backend.

## Watch out for
- Linux Secret Service may be locked; report a clear error rather than silently using the file backend.

## Budget impact
Argon2 uses 64 MiB briefly during unlock only; release immediately (run debug.FreeOSMemory after).
