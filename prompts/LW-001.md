# Task LW-001: Repository, Go module and tooling
Milestone M0 (Foundations) · Priority P0 · Estimate 1 d · Step 1 of 48

## Your role
You are a senior engineer (Go, TypeScript and Preact) building Wisp, a local database client for PostgreSQL, MySQL and MariaDB. One Go binary serves a private HTTP server on 127.0.0.1 and the UI runs in the browser (Preact + TypeScript, built with Vite, styled with Tailwind CSS v4). Low memory for the Go process and for the browser tab is a deal breaker. Read AGENTS.md at the repository root before you start; its rules apply to this task.

## What to build (do these steps in order)
1. Run go mod init; set the go directive to the current stable Go (1.24 or later). CGO must stay disabled: add `export CGO_ENABLED=0` to the Makefile.
2. Create each internal package with a doc.go whose package comment states what the package owns and which packages it may import (see AGENTS.md section 2).
3. Create web/package.json with exact pinned versions (no ^ or ~). Dependencies: preact, @preact/signals. devDependencies: vite, @preact/preset-vite, tailwindcss, @tailwindcss/vite, typescript, vitest, @testing-library/preact, happy-dom. Scripts: dev (vite), build (vite build), check (tsc --noEmit), test (vitest run).
4. web/tsconfig.json: strict true, noUncheckedIndexedAccess true, jsx react-jsx, jsxImportSource preact, module esnext, moduleResolution bundler, target es2022, noEmit true. Do NOT add a paths alias for react or install preact/compat.
5. Makefile targets: web (npm ci && npm run build in web/), build (web then go build -trimpath -ldflags '-s -w -X main.version=$(VERSION)' -o bin/wisp ./cmd/wisp), test (go test ./... and npm --prefix web test), lint (gofmt check, go vet, golangci-lint run, npm --prefix web run check), dev (runs vite dev server and go run ./cmd/wisp -dev together). size, bench and gate come in LW-005.
6. .golangci.yml enabling errcheck, govet, staticcheck, gosec, revive, unused, ineffassign, bodyclose, noctx.
7. Add a test in internal/bench (placeholder) that parses `go list -deps` and fails if an internal package imports a package it is not allowed to (import rules from AGENTS.md).
8. Copy AGENTS.md, CLAUDE.md, GLOSSARY.md, .claude/skills/tdd/, docs/PRD.md and design/ from the pack into the repo root.

## How to work
Follow the TDD skill (.claude/skills/tdd/SKILL.md) and AGENTS.md section 6.
1. First reply with a plan: files you will touch, approach per step, and how each acceptance criterion will be proven.
2. In the same reply, list the seams you propose to test (start from the section above). For each: the public interface, one line on what it catches, one line on what it misses. Then STOP and wait for me to confirm the seams. Do not write any test or code before that. (If this ticket has no code under test, say so and continue.)
3. After confirmation, work in vertical slices: one seam, one failing test (red), the minimal code to pass it (green), run the tests, commit. Repeat. Never write all tests first.
4. Test only through public interfaces; fake only system boundaries (database, network, clock, filesystem). Expected values come from the spec or literals, never recomputed like the code does.
5. Do not refactor inside the loop; collect refactor ideas for the report.
6. Commit messages start with the task id (e.g. "LW-001: add ..."). If the task conflicts with AGENTS.md, docs/PRD.md or existing code, stop and explain instead of guessing. Do not start the next ticket.

## Final report
End with the report format from AGENTS.md section 8: summary, files changed, confirmed seams and the tests written for each, each acceptance criterion with PASS/FAIL and evidence, measurements, dependencies added, refactor ideas, open questions.
