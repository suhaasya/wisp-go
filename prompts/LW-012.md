## Goal
One Driver interface for all engines and a compact column-wise Window type that is cheap to hold in Go and cheap to encode as JSON.

## Why this matters
How rows are stored decides whether the 1M-row budget is reachable. Column-wise windows with one byte arena avoid millions of small allocations.

## What to build (do these steps in order)
1. Define Driver and Conn interfaces (see interface). All methods take context.Context and honour cancellation.
2. Window: Columns []ColumnMeta; Rows int; per column a typed vector: ints []int64, floats []float64, bools []bool, or offsets into one shared []byte arena for text/decimal/json/bytes/dates (dates formatted once as ISO strings); null bitmap per column; truncated flag per cell for values over 4 KB (only first 4 KB stored).
3. Window.MarshalJSON writes the PRD wire format directly to a pooled bytes.Buffer (no intermediate maps).
4. Dialect interface: QuoteIdent, QuoteLiteral, Placeholder(n), LimitOffset, KeysetPredicate, Name.
5. Mock driver generating deterministic rows for N×M (used by UI tickets before real drivers).
6. Benchmark: building + encoding a 150×10 window of 20-char strings: allocations ≤ 30, heap ≤ 1.5× raw data.

## Interface to implement (adapt names if needed; keep the shape)
```go
type Driver interface { Open(ctx context.Context, p ConnectParams) (Conn, error); Name() string }
type Conn interface {
  Ping(ctx context.Context) (time.Duration, error)
  ServerInfo(ctx context.Context) (ServerInfo, error)
  Exec(ctx context.Context, sql string, args ...any) (ExecResult, error)
  Query(ctx context.Context, sql string, args ...any) (Rows, error) // streaming, caller reads windows
  Begin(ctx context.Context) (Tx, error)
  Dialect() Dialect
  Close() error }
type Rows interface { Columns() []ColumnMeta; NextWindow(max int) (*Window, error); Close() error }
```
