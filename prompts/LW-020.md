## Goal
Reach databases behind bastions through SSH (keys, passwords, agent, ~/.ssh/config, known_hosts), including up to three jump hosts.

## Why this matters
Production databases usually sit in private networks. golang.org/x/crypto/ssh handles this in pure Go.

## What to build (do these steps in order)
1. Auth order: agent (SSH_AUTH_SOCK; Pageant/OpenSSH agent pipe on Windows via golang.org/x/crypto/ssh/agent) → key file (+ passphrase from secrets) → password.
2. Parse ~/.ssh/config for Host, HostName, User, Port, IdentityFile, ProxyJump (small parser, no dependency).
3. known_hosts via golang.org/x/crypto/ssh/knownhosts. Unknown host: return a HostKeyNeeded error with type and SHA256 fingerprint; the page shows a modal; on 'Trust', POST /hostkeys/accept appends to known_hosts and the connect is retried. Mismatch: hard error, no override.
4. Tunnel: client.Dial("tcp", db) returns a net.Conn; pass it to pgx via DialFunc and to mysql via RegisterDialContext (per-session network name).
5. Jump hosts: for each hop dial through the previous client and create a new ssh.Client over that connection; max 3 hops.
6. Pool: share one ssh.Client per (chain) among sessions; keep-alive requests every 30 s; on failure notify sessions to reconnect.
7. SSH tab UI: enable, host, port, user, auth method, key path (file picker), passphrase, jump host list (add, remove, reorder).
