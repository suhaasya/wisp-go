## Goal
Run the current statement, the selection or the whole script; show each result in its own tab; cancel slow queries; view EXPLAIN plans.

## Why this matters
Running SQL is the second core workflow; results reuse the pager and grid so big results stay cheap.

## What to build (do these steps in order)
1. POST .../run {sql, cursor | selection | all} → qid; statements run sequentially; progress over SSE; each result-returning statement opens a pager result (rid).
2. Every statement passes the write guard; needsConfirmation → confirm dialog then re-run with confirm.
3. Result tabs: keep the 5 most recent results open in Go; older ones are closed (re-run to view).
4. Messages tab: rows affected, duration, notices, errors with line and position; the editor highlights the error position.
5. Cancel button and Esc → POST .../cancel/{qid} → context cancel.
6. Explain: PG EXPLAIN (FORMAT JSON [, ANALYZE]); MySQL EXPLAIN FORMAT=JSON; render as an indented tree (node, relation, cost, rows, time). ANALYZE on writes requires confirmation.
7. Results editable only when they map to one table with a PK.
