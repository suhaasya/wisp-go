## Goal
Open a result for a table browse or query, keep at most three windows of rows in Go, and serve any window to the page on request.

## Why this matters
This is the memory control for both sides: Go never holds whole results, the tab never holds more than the screen.

## What to build (do these steps in order)
1. POST /sessions/{sid}/results {source: {kind: table, schema, table, filters, sort} | {kind: query, sql}} → {rid, columns, total}.
2. Strategy: Keyset when browsing a table with PK or unique not-null key (ORDER BY sort cols + pk; WHERE (cols) > (last) LIMIT n); Cursor for queries (PG: DECLARE … CURSOR inside a read-only transaction with FETCH; MySQL: streaming rows held open, forward only, plus OFFSET re-query for backward jumps); Offset as fallback.
3. Window cache: LRU of WindowsInMemory windows per result; GET .../window?offset=&limit= returns from cache or fetches.
4. Total: exact COUNT(*) when estimate < 100k; else estimate (pg_class.reltuples, information_schema TABLE_ROWS) marked estimate; POST .../count runs exact count cancellably.
5. Overlay of staged edits (LW-029) applied when encoding windows.
6. Close results on DELETE, when their session closes, or after 10 minutes unused.
7. Property test on a 100k-row fixture: random window requests equal the rows of a full ordered SELECT.
