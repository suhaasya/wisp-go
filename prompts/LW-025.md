## Goal
Show table data in a spreadsheet-style grid whose DOM size never grows with the table, fetching windows from Go as the user scrolls.

## Why this matters
The grid is where users judge speed, and where web apps usually waste memory. A fixed row pool and windowed data keep the tab tiny. The grid is the one place that does not render through Preact: a Preact component owns the container, and a plain TypeScript module manages the row pool and writes cells directly, so no virtual DOM diff runs per scroll frame.

## What to build (do these steps in order)
1. Grid.tsx is a Preact component that renders the scroll container and header shell, then hands a ref to pool.ts in useEffect. pool.ts (plain TypeScript, no JSX) creates, positions and updates row elements directly; the effect cleanup destroys it.
2. Structure: a scroll container with a spacer element sized to total rows × row height; a fixed pool of (visible rows + 10) row elements positioned with transform: translateY.
3. Columns virtualised horizontally: render only visible columns plus 2; sticky header row and sticky row-number column (44 px).
4. buffer.ts keeps at most 3 windows (offset → columnar data) from GET .../window; requests the next window when the viewport is within half a window of an edge; aborts superseded requests.
5. Cells: textContent only; numbers right-aligned; NULL italic null-text colour; values truncated by Go shown with an ellipsis icon; enum values as pills.
6. Header: name + type (mono 10.5 px); resize by dragging; reorder by dragging; hide via menu.
7. Selection: cell, range (Shift), row (row number), copy as TSV, CSV or INSERT (large copies requested from Go as text).
8. Status bar: Rows a–b of total, last fetch time.
9. Rows not yet loaded show a faint placeholder bar; never block scrolling.
