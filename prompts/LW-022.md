# Task LW-022: Schema introspection and metadata cache
Milestone M1 (Connect and browse) · Priority P0 · Estimate 3 d · Step 22 of 48

## Goal
List databases, schemas and objects lazily per level, and table details on demand, with a bounded cache.

## Why this matters
Sidebar, autocomplete, structure view and grid headers all need metadata; lazy loading keeps memory flat for huge schemas.

## What to build (do these steps in order)
1. Introspector interface: Databases, Schemas, Objects(schema, kind), TableDetails(schema, table) → columns, primary key, foreign keys, indexes, checks, triggers.
2. PostgreSQL via pg_catalog (relkind r, v, m, p, f, S; pg_proc; pg_type enums; pg_constraint; pg_index); hide system schemas by default.
3. MySQL/MariaDB via information_schema filtered by TABLE_SCHEMA.
4. One query per level, never per table; run on the metadata Conn.
5. Cache: object lists per schema and an LRU of TableDetails (max 2,000); invalidate on DDL and refresh action.
6. API endpoints as in the PRD with compact JSON (arrays, not verbose objects, for object lists).
