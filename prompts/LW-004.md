# Task LW-004: Frontend build: Vite, Preact, TypeScript, Tailwind v4, embedding

## Your role
You are a senior engineer (Go, TypeScript and Preact) building Wisp, a local database client for PostgreSQL, MySQL and MariaDB. One Go binary serves a private HTTP server on 127.0.0.1 and the UI runs in the browser (Preact + TypeScript, built with Vite, styled with Tailwind CSS v4). Low memory for the Go process and for the browser tab is a deal breaker. Read AGENTS.md at the repository root before you start; its rules apply to this task.

## Goal
One command builds the minified, content-hashed frontend with Vite and the Go binary embeds it; in development, Vite's dev server gives instant hot reload while Go serves the API.

## Why this matters
The frontend is part of the binary. Vite gives fast hot reload while building screens and outputs plain static files that go:embed serves.

## What to build (do these steps in order)
1. vite.config.ts: plugins [preact(), tailwindcss()] from @preact/preset-vite and @tailwindcss/vite; build.target es2022; build.assetsDir 'assets'; build.manifest true; build.modulePreload { polyfill: false } (no inline polyfill, keeps CSP strict); build.sourcemap false; rollupOptions.output.manualChunks only for the editor (see LW-031).
2. index.html: <div id=app>, <script type=module src=/src/main.tsx>. No inline scripts or styles. Vite injects hashed asset links at build time.
3. main.tsx: render(<App/>, document.getElementById('app')!) using preact's render. App is a placeholder until LW-009.
4. web/embed.go exposes dist as an fs.FS; internal/server/static.go serves /assets/* (immutable cache) and index.html (no-store; nonce templating comes from LW-003).
5. Dev mode: `make dev` starts `vite` on 127.0.0.1:5173 and `wisp -dev`. In dev mode Go reverse-proxies non-API paths to Vite (including its HMR websocket) so the page, cookies and API share one origin; the CSP in dev mode additionally allows Vite's HMR connect source.
6. tools/sizes.ts (run with `node --experimental-strip-types` or tsx devDependency) reads the Vite manifest and writes dist/sizes.json with gzip sizes of the initial JS, lazy chunks and CSS for the LW-005 gate.

## Acceptance criteria (every one must pass)
- `make build` produces a binary that serves the page with no files on disk.
- Hashed assets are served with immutable caching; index.html with no-store.
- In `make dev`, editing a component updates the page in under 1 s without a full reload.
- Initial JS (Preact + signals + placeholder app) is under 15 KB gzip.
