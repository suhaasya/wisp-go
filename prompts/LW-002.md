## Goal
`wisp` starts a server on a random loopback port, opens the browser at a one-time URL, reuses an already running instance, and shuts down cleanly.

## Why this matters
This is the product's front door. It must feel instant, never leave zombie processes, and never open two servers for one user.

## What to build (do these steps in order)
1. Flags: --port (default 0 = random), --no-browser, --app, --dev (serve web/ from disk), --idle-exit (default 10m), --log-level; subcommands: stop, version, --update (stub until LW-047).
2. Paths via os.UserConfigDir / os.UserCacheDir under 'wisp'; runtime dir holds instance.json {pid, port, started} with 0600 permissions.
3. Single instance: take an exclusive lock on runtime/instance.lock (flock on Unix, LockFileEx on Windows via golang.org/x/sys). If locked, read instance.json, call POST /internal/handoff on that port with a shared secret file (0600) to get a fresh one-time login URL, open the browser at it, and exit 0.
4. Open browser: macOS `open`, Linux `xdg-open`, Windows `rundll32 url.dll,FileProtocolHandler`. --app: look for Chrome/Edge/Chromium in standard locations and run with --app=<url>; fall back to the default browser.
5. Graceful shutdown on SIGINT/SIGTERM/`wisp stop`: stop accepting, close sessions (LW-021 hook), flush journal hook, remove instance.json, exit within 2 s.
6. Idle exit: when no SSE client has been connected for --idle-exit, shut down (hook from LW-009 events).
7. Print to stdout one line: `Wisp running at http://127.0.0.1:<port>/ (press Ctrl+C to stop)` (never print the token).

## Acceptance criteria (every one must pass)
- Second `wisp` invocation opens a new browser tab connected to the first instance and exits.
- `wisp stop` stops the running instance within 2 s and removes instance.json.
- Process start to listening socket ≤ 100 ms (measured with a timer in debug log).

## Proposed seams and tests (starting point: confirm the seams with me before writing any test)

## Watch out for

- Windows: the lock must be released if the process crashes (OS handles file locks; test it).
