## Goal
Edit cells and rows in the grid and panel; every change is staged in Go (not the browser), shown with yellow/green/red markers, and survives page reloads.

## Why this matters
Keeping the change set in Go makes the tab lighter and makes edits crash-safe for free: reload the page and your staged edits are still there.

## What to build (do these steps in order)
1. ChangeSet per result keyed by row identity (PK values): updates {col → new, original}, inserts (temp ids), deletes. Merge rules: edit after insert edits the insert; delete after insert removes it; editing a deleted row is refused; reverting to the original removes the update.
2. API: POST .../changes {op: set|insert|delete|revert, ...} returns {count}; DELETE .../changes discards.
3. Window encoding adds the overlay (mod cells, ins rows, del rows) so the page renders states without keeping its own copy.
4. Grid editing: double-click/Enter opens an inline editor; Esc cancels; Tab moves; Ctrl/⌘+Backspace sets NULL; menu Set NULL / Set DEFAULT / Revert.
5. Typed editors: bool toggle, date/time text with validation, enum dropdown (values from metadata), JSON editor with validation, text.
6. Toolbar: Add row, Duplicate row, Delete row, Discard, 'Review SQL (n)' warning button; status bar shows staged count in env-staging colour.
7. Tables without PK or unique key: editing disabled with a banner explaining why. Read-only sessions disable all edit controls.
8. Change sets are journaled to disk by LW-035.
